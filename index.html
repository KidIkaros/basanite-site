01 // how it works

Three steps. No platform in the middle.

[1] seal_

Capture becomes proof

basanite seal binds the file's exact bytes into a signed manifest — Ed25519 + Falcon-1024, post-quantum from day one.

[2] edit_

History stays honest

Every change appends a signed checkpoint. Rewrites are visible; deletions can't quietly vanish.

[3] verify_

Anyone can check, offline

Signatures and hashes check out or they don't. Three verdicts. exit 0 only for intact.

03 // three verdicts, never a score

The whole truth table.

manifest-intact

Every checkpoint signature and content hash verified, end to end.

manifest-invalid

Something doesn't match. The reason says exactly what, and where.

no-manifest

No provenance claim found. Honest absence — never a guess.

Others score how fake a file might look. basanite proves what happened to it. Detection guesses what a file is; we prove what happened to it — post-quantum signatures, offline verification, keys that answer to you and no one else. The verdict is a cryptographic statement about the manifest, not a guarantee of ground truth.

04 // straight answers

Questions this page
would be incomplete without.

Is this deepfake detection?

No. Detection guesses what a file is; basanite proves what happened to it. They're complements. If a file carries no manifest we say no-manifest — we don't pretend to know.

What if I lose my key?

The manifest stays verifiable — proofs don't die with the key. New work continues under a new key. There is no recovery server, by design.

Why not just use C2PA?

C2PA is a committee standard with a trust-list gate and documented security-goal failures in academic audit. basanite's format is independent, the verifier is free forever, and revocation is a first-class check, not an afterthought.

Does the verifier phone home?

No. No telemetry, no account, no network call. Verification is local.
