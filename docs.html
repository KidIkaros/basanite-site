Docs · verdicts

Three verdicts.
Exactly what each means.

Every basanite verify ends in one of three states, printed in plain language with an exit code scripts can trust. The output below is real (v0.1.6), not an illustration.

1 · manifest-intact — exit 0

$ basanite verify clip.wav

manifest-intact as of 1790111062
  chunks: 1/1 matched
  signer: c26cb9387ac8be593f30c519ae201c316ede2c1743411bb4b48606d35d0bed6a
  manifest_id: 75ce27c2a812277f0a4e130e99b2eabfdef0f1ce54f5fa6d07dd9c235be5bd64
  note: no publisher head anchor was applied — a shortened edit history cannot be detected from the manifest alone (see 'basanite anchor --help')
  checked: canonical edit order, content binding (whole file + chunks), MMR replay at every checkpoint, checkpoint signatures (Ed25519+Falcon), timestamp sanity, attestation binding. revocation NOT checked: no journal found (absence of a journal is not evidence of absence of revocation). not checked: metadata (ignored), watermark (hint only), timestamps are signer-asserted not TSA-attested.

This means:

  • The bytes you verified are the bytes that were sealed or edited, at every step of the recorded history — content hashes, checkpoint signatures (Ed25519 + Falcon), and the MMR replay all check out.
  • The history that is present is internally consistent — nothing in it was forged, reordered, or rewritten.
  • It does not prove this is the WHOLE history. Without the publisher's signed head anchor (basanite anchor, the .anchor file beside the asset), a shortened history is indistinguishable from a short one. The verdict says plainly when no anchor was applied — that note is part of the output above.
  • It does not prove ground truth. A verdict is a cryptographic statement about the manifest — not a judgment that the underlying events happened as described.

2 · manifest-invalid — exit 1

$ basanite verify clip.wav

manifest-invalid (content-hash: chunk 0)
  reason: ContentHash { chunk: Some(0) }
  checked: canonical edit order, content binding (whole file + chunks), MMR replay at every checkpoint, checkpoint signatures (Ed25519+Falcon), timestamp sanity, attestation binding. revocation (not enforced on this failure path). not checked: metadata (ignored), watermark (hint only), timestamps are signer-asserted not TSA-attested.

This means:

  • The file's present bytes do not match the sealed history — in this example, the first content chunk's hash no longer matches. The reason names exactly what failed and where.
  • Do not trust the file's content. If the change was yours (a normal edit without re-sealing), re-seal is not the answer — edit through the tool so the history records it. If the change was not yours, treat the file as tampered: preserve it and see the flagged-asset runbook.
  • Exit code 1 by contract. basanite verify file && publish file halts on tampering — a tampered file cannot pass a scripted gate.
  • It does not tell you who changed the file. The verdict locates the mismatch; attribution lives in your custody chain, not in cryptography.

3 · no-manifest — exit 1

$ basanite verify other.txt

no-manifest (no sidecar at other.txt.opm)
  discovery: no sidecar at other.txt.opm
  discovery: no watermark marker found
  checked: canonical edit order, content binding (whole file + chunks), MMR replay at every checkpoint, checkpoint signatures (Ed25519+Falcon), timestamp sanity, attestation binding. revocation (not reached — no manifest found). not checked: metadata (ignored), watermark (hint only), timestamps are signer-asserted not TSA-attested.

This means:

  • No provenance claim exists for this file — no sidecar manifest, and no watermark hint pointing at one. Nothing was checked, because there was nothing to check against.
  • Exit code 1 by contract. "No claim" is not "authentic" — unverified is unverified, and scripts treat it the same as tampered.
  • It does not mean the file is fraudulent. It means no history was ever sealed (or the sidecar was lost — see the runbook for recovery).

The footer is the honesty clause

Every verdict — all three states — prints the same footer: what was checked, what was not, and whether revocation was enforced. If a journal was present, revoked signers fail the manifest. If none was found, the footer says so — absence of a journal is not evidence of absence of revocation.
